# AGENTS.md

The cookout: a self-hosted, Slack-style board for people and agents. Spec: mattpocock/cookout#1.

- [GLOSSARY.md](GLOSSARY.md): the domain language. Names in code use its terms.
- `pnpm check` runs the checks CI runs through `scripts/check.ts`, browser tests included. The e2e suite (`packages/e2e` on the Docker image) runs only on CI, as the Release workflow's `e2e-docker` job before it publishes ([ADR](docs/adr/0088-the-e2e-suite-runs-only-on-ci.md)); run it on purpose with `pnpm e2e:docker`. Pack smoke and the published client run only there too. The Check workflow runs on pushes to `v1` and on `workflow_dispatch` only, never on `ticket-*` pushes or pull requests, with 8 jobs: `static` (lint, canaries, types, fixers, seams, knip, format and drift, one step each, stopping at the first that fails), `tests` ×3, `browser` ×3 and `coverage`; a worker's own `pnpm check` is the check before it lands, and v1's Check covers the merged result ([ADR](docs/adr/0111-a-worker-lands-its-own-pull-request-with-no-checks-after-merging-v1.md)). Run `pnpm check` once before you finish; it must exit 0. Its hygiene step refuses a migrations list that doesn't begin with the newest `deploy/*` tag's, or with v1's at the merge base with origin/v1, entry for entry, and an ADR number taken twice. `pnpm check` refuses a change that loosens the lint config (in `.oxlintrc.json` a rule turned off or downgraded, an added or widened override or an added ignorePatterns entry; an added entry in `docs/lint-opt-outs.md`; any change to `.dependency-cruiser.cjs`), naming the file and the hunk, and refuses what it can't tell tightens; a new rule, its own owner exemption or a `warn` made `error` passes. Its drift job judges the change against the merge base with origin/v1 locally, and the push's range on v1's Check ([ADR](docs/adr/0109-the-lint-config-guard-runs-in-the-check-and-approval-is-a-commit-trailer.md)). Only Matt approves a loosening: the commit that makes it carries the trailer `Lint-approved-by: board msg <id>`, naming his message. With a clean working tree (nothing uncommitted or untracked) and a green push Check run at HEAD (only on `v1`), it runs nothing and prints `RESULT: PASS (CI green at HEAD <run url>)`; when `gh` is missing or fails it says so in one line and runs everything, and `--ci` and `--job` runs never skip. Before its verdict it prints one `skipped:` line naming the e2e suite. Locally it runs only the browser tests the branch reaches, and runs them all when it can't tell ([ADR](docs/adr/0092-local-check-runs-only-the-browser-tests-a-branch-reaches.md)); CI runs them all. For a change to the served app (a view) it picks them from the coverage map CI's browser job records and the check fetches with `gh`, and runs them all when there is no map or it is stale ([ADR](docs/adr/0096-a-local-check-picks-browser-tests-from-ci-s-recorded-coverage.md)). When every file changed against origin/v1 is docs (`*.md`, `docs/`, `.changeset/`, deletions included), it skips the tests and browser jobs and says so in one line; the rest (docs drift, format and so on) still runs, and CI still runs everything. When it skips some, a second `skipped:` line names them; `pnpm browser` runs them all. Its last line is its verdict, after any time budget warnings: `RESULT: PASS` or `RESULT: FAIL (<failed checks>)`. It waits while another `pnpm check` or `pnpm coverage:changed` runs on the machine, printing one line on stderr that names the worktree it waits for (CI doesn't wait). Its first line is the machine's 1-minute load average and core count; when the load is above the core count it warns on stderr, since browser tests then time out at random.
- `pnpm coverage:changed` runs the tests and lists, as `file:line`, every uncovered line or branch in files changed against v1. Run it before `pnpm check` to catch a coverage gap early. It waits for the same machine-wide lock as `pnpm check`. Its last line is its verdict: `RESULT: PASS` or `RESULT: FAIL (<failed step>)`, the step being `tests` or `uncovered lines`.
- Land your own pull request by these steps, with no review and no merge queue ([ADR](docs/adr/0111-a-worker-lands-its-own-pull-request-with-no-checks-after-merging-v1.md)):
  1. Commit with `scripts/commit.sh`.
  2. Run `pnpm check` after the last commit. Its last line must be `RESULT: PASS`.
  3. Push the branch, and open the pull request against v1 (`gh pr create --base v1`) if it isn't open yet.
  4. `git fetch origin v1`, then `git merge --no-edit origin/v1`.
  5. On a conflict, resolve it: for a generated file, rerun its generator (`pnpm validators`, `pnpm api:write`, `pnpm lint:baseline`); in a migrations list, keep v1's entries first and yours after them; in Vitest's coverage thresholds, keep the lower number. Commit with `scripts/commit.sh`, run `pnpm check` again, and go back to step 4.
  6. With no conflict, run no checks. `git push`, then `gh pr merge <PR> --merge`. If GitHub refuses because v1 has moved and now conflicts, go back to step 4.
  7. Close the ticket's issue: `gh issue close <N> --comment "Landed on v1 in <merge commit SHA>"`, with the SHA from `gh pr view <PR> --json mergeCommit --jq .mergeCommit.oid`.
  8. Don't wait for v1's Check run. You're done.

  A clean `git merge` of v1 makes its commit without the pre-commit hook, and v1's Check covers the merged result. If a red v1 follows, a fix-forward ticket goes first, and it lands by the same steps.
- `pnpm ci:wait` waits for the Check push run of HEAD (on a `ticket-*` branch there is none, so it fails once it has waited 10 minutes for one), polling every 30 s, prints each job's conclusion and each failed job's failed steps, then each failing Vitest or Playwright test in its log (file, name and the first lines of its error), then its last 20 log lines, and exits 0 only if every job passed (a job that failed only on a time budget warns). Its last line is its verdict: `RESULT: PASS` or `RESULT: FAIL (<failed jobs>)`. It judges the commit, not one run: the commit is green if any completed run on it succeeded, a cancelled run never counts as red, and if every run on it was cancelled it reruns the newest once. A job cancelled after running for about its `timeout-minutes` in `.github/workflows/check.yml` was cut off at its time limit, not superseded: then it names each such job and its limit, doesn't rerun, and exits 3 (other failures exit 1), with `RESULT: FAIL (<jobs> cut off at its time limit)`. `pnpm ci:wait --sha <sha> --branch v1` watches a merge on v1. Use it to watch v1; never hand-write `gh run watch`, and never pipe a watch, since a pipe hides its exit code.
- `pnpm lint:changed` runs the hook's lint (same rules and baseline ratchet) and type check on files changed against origin/v1, staged, unstaged or untracked, without committing or fixing, then `pnpm knip` on the whole repo, so an unused export, file or dependency fails here with knip's report rather than after the tests in `pnpm check` or on v1's Check run. It prints each new violation once, in the hook's format (including ones the hook would fix for you), and exits non-zero if there are any. It ends with a summary by rule: each failing rule's count and its first violation, most frequent first, capped at 40 lines. Its last line is its verdict: `RESULT: PASS` or `RESULT: FAIL (<failed checks>)`, the checks being `lint`, `types` and `knip`. Run it while you work to see lint early.
- Don't run fix, format or other lint commands yourself. Commit, and the pre-commit hook fixes and formats what you staged; then fix by hand only what it prints as left over: each new violation once, as `file:line rule message`, then "N new violations in M files". Commit with `scripts/commit.sh`, which takes `git commit`'s arguments: lefthook skips the whole hook when nothing is staged, so it fails then with "nothing staged: run git add first".

- Only Matt approves a domain term. A term counts as approved only with a dated decision of Matt's cited next to it, in an ADR under `docs/adr/` or a comment on a mattpocock/cookout issue; without one it stays proposed.
- In a git worktree, create files with the Write tool (not `cat > … <<EOF`), run every command from the worktree root, and add root dependencies with `pnpm add -w`.
